## 背景

- 2026-10-28 P0007 T1 第 1 輪：writer 21:28:47 已交出結果，但它啟動的完整品質檢查（被 Claude Code 自動轉到背景，之後又明確用背景執行跑了一次）讓 claude.exe 不退出，任務停在「寫程式中」，總覽跳出「卡住」。
- 同一天量測：完整測試純 pytest 約 7 分半到 11 分（視 CPU 負載），加上 coverage 約 11 分半；不碰瀏覽器與 conductor 整合測試的測試檔，大多在 20 秒內跑完，所以「只跑相關測試」可行。
- 依據 Obsidian 筆記「Harness 工程」與「Harness 工程的實作應用」：讓 agent 有快速的回饋（眼睛），規則寫成機械約束而不是靠 agent 記得。
- R3 的依據：P0007 三輪 writer 的 log 中，PowerShell 的 `& "D:/MAMD/.venv/Scripts/python.exe" ...` 每次都被拒，Bash 的 `"D:/MAMD/.venv/Scripts/python.exe" ...` 都通過；2026-10-29 用 claude -p（haiku、--permission-prompts none）實測，`& "路徑" --version` 對 `PowerShell(& "路徑" --version*)`、`PowerShell("路徑" --version*)`、`PowerShell(路徑 --version*)` 三種規則都被拒，不加引號、不用 & 的指令與規則才通過；Claude Code 文件說明 PowerShell 規則會先解析成語法樹再比對，確切的比對方式文件沒寫，不確定。

## 範圍

- 不包含：不穩定測試的重跑規則、讓完整測試變快（瀏覽器測試共用、依改動選測試）、限制同時跑的完整測試數量；這些之後另寫 plan。
- Codex 只套用 R1 的 prompt 調整；R2 依 Claude 的 result 事件判斷，目前沒觀察到 Codex 交出結果後不退出，不改 Codex 的結束判斷；R3 只改 Claude writer，Codex 的 PowerShell 寫法維持不變。
- R3 假設 Windows 上的 Claude Code 有 Bash 工具（需要 Git for Windows；這台電腦的 writer log 顯示 Bash、PowerShell 兩個工具都有），沒有 Bash 工具的環境不在這次處理範圍。
